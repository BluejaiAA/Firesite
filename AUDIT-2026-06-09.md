## Findings

### 🟡 Risk 1 — Logo loaded from `raw.githubusercontent.com`

The marketing landing page loads `firesite_logo.png` from:

```
https://raw.githubusercontent.com/BluejaiAA/Firesite/main/firesite_logo.png
```

**Why this matters:**
1. If the repo is ever made private, the logo 404s and the marketing page breaks.
2. `raw.githubusercontent.com` is not a Vercel asset — it's outside our CSP `img-src` if we tighten that header later.
3. GitHub's raw endpoint is **not a CDN** and is rate-limited.
4. The PNG **is also committed at the repo root** so it could be served directly from `firesite-weld.vercel.app/firesite_logo.png` (verified, returns 200).

**Fix:** edit `index.html` to change the `<img src="...">` from the raw GitHub URL to `/firesite_logo.png`. One-line, low-risk PR. **Not done in this audit** — flagged for next PR.

### 🟡 Risk 2 — Sentry SDK loaded but inert

`window.Sentry` is present in the app context but `window.SENTRY_DSN` is not set. This means:
- The SDK bundle is downloading (cost: ~50KB and a CDN round-trip on every load)
- ErrorBoundary's `Sentry.captureException` calls are silent no-ops
- Any production errors are NOT being captured anywhere

**Fix:** either (a) sign up for Sentry free tier and paste the DSN into the `window.SENTRY_DSN` line near the top of `app.html`, or (b) strip the Sentry SDK `<script>` until you're ready. Option (a) is recommended given how cheap free tier is.

Carryover from Phase 1 (2026-05). Already in CONTEXT.md as outstanding.

### 🟢 Good — CSP is enforced (not Report-Only)

PR #2 from 29 May flipped `Content-Security-Policy-Report-Only` → `Content-Security-Policy`. Live response confirms the enforcement header is present and the Report-Only header is gone. No CSP violations observed during smoke test.

### 🟢 Good — Firestore connection healthy

The app opens a long-poll listen channel to `firestore.googleapis.com` for the `firesiteapp` project on every load. Status 200, no auth errors. Confirms the multi-tenant rules deployed on 29 May 2026 08:55 are not blocking authenticated reads of the user's own profile.

### 🟢 Good — No drift since last touch

Last main-branch commit landed 2026-05-31. `vite-lite` branch (now 13 commits ahead) has not been merged — main is serving the same code we last reviewed. No surprise regressions.
